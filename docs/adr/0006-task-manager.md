# ADR 0006: 작업 관리자: 프로세스 정보 수집, 갱신, 종료

- 상태: **채택** (2026-11-18)
- 관련: SPEC 7.9, 10(Phase 6), 7.8(My PC의 "사용 중" 안내), 7.2.1(sudo 비밀번호 규칙)

## 1. 프로세스 정보: `/proc` 직접 읽기

| 방식 | 장점 | 단점 |
|---|---|---|
| **`/proc` 직접 읽기** | 외부 명령 없음. 리눅스라면 어디에나 있고 형식이 안정적. 2초마다 읽어도 프로세스를 새로 띄우지 않음 | 리눅스 전용. 필드 해석을 직접 해야 함 |
| `ps -eo ...` 실행 | 해석이 쉬움 | 갱신할 때마다 프로세스를 띄움. procps 버전·로캘에 따라 출력이 달라짐. CPU %가 "지금"이 아니라 수명 평균 |
| gopsutil 같은 라이브러리 | 여러 OS 지원 | 의존성 추가(규칙 8). 필요한 것은 리눅스의 몇 개 파일뿐 |

**결정: `/proc` 직접.** 읽는 파일은 프로세스마다 `stat`, `status`, `cmdline`, 시스템 전체는 `meminfo`, `stat`, `loadavg`, `uptime`입니다.

- `stat`의 이름은 괄호 안에 있고 이름 자체에 공백·괄호가 들어갈 수 있어, 마지막 `)`부터 필드를 셉니다.
- 메모리는 `status`의 `VmRSS`(kB)를 씁니다. 페이지 크기를 알 필요가 없습니다. `VmRSS`가 없고 명령줄이 비어 있으면 커널 스레드로 봅니다.
- CPU %는 두 스냅샷의 차이로 계산합니다: (프로세스 틱 증가) ÷ (전체 CPU 틱 증가) × 코어 수 × 100. 코어 하나를 다 쓰면 100입니다(`top`과 같음). 초당 틱 수(`CLK_TCK`)를 알 필요가 없습니다.
- 읽는 도중 끝난 프로세스는 건너뜁니다.
- 모든 접근은 `procs.Source`(파일 읽기, 폴더 목록, 링크 읽기)를 거치므로 테스트는 픽스처로 하고 실제 `/proc`을 읽지 않습니다.
- macOS(개발 환경)에는 `/proc`이 없습니다. 창은 열리고 그 사실을 알립니다.

## 2. 갱신: 창 단위 타이머

- 창이 열려 있는 동안 고루틴 하나가 주기(기본 2초, 1/2/5초, 일시 정지)마다 스냅샷을 읽어 UI 고루틴에 넘깁니다(`host.Post`). 읽기는 UI 고루틴 밖에서 합니다.
- 창을 닫으면 고루틴이 끝납니다. 작업 관리자를 열지 않으면 아무것도 주기적으로 돌지 않습니다(규칙 9).
- 화면은 달라진 셀만 다시 씁니다(기존 렌더러). 최소화된 동안에도 읽기는 계속합니다. 비용이 작고, 다시 열었을 때 CPU %가 바로 맞습니다.
- 선택은 줄 번호가 아니라 PID로 기억합니다. 정렬 순서가 바뀌어도 선택이 다른 프로세스로 옮겨 가지 않습니다. CPU·메모리가 같으면 PID 순으로 두어 목록이 흔들리지 않습니다.

## 3. 종료: 신호는 직접, 남의 프로세스만 sudo

- End task = `SIGTERM`, Force quit = `SIGKILL`. 둘 다 확인창을 거칩니다.
- 자기 프로세스는 `kill(2)`을 직접 부릅니다. 다른 사용자의 프로세스는 `sudo kill -TERM|-KILL <pid>`로 보냅니다(에디터의 sudo 저장, My PC와 같은 `host.RunSudo`). 앱을 root로 실행한다고 가정하지 않습니다(규칙 7).
- 막는 것: PID 1, 커널 스레드, tuidesk 자신.
- 경고하는 것: tuidesk의 조상 프로세스(셸, sshd 세션). 끝내면 tuidesk도 같이 끝납니다.
- `ESRCH`(이미 끝남)는 에러가 아니라 알림입니다.
- PID 재사용: 확인창이 떠 있는 사이 그 PID가 끝나고 다른 프로세스가 같은 번호를 받을 가능성이 이론적으로 있습니다. 리눅스의 PID는 순서대로 돌아가며 배정되어 몇 초 안에 재사용될 일은 사실상 없으므로 따로 막지 않았습니다. 문제가 되면 `pidfd`로 바꿉니다.

## 4. "누가 이 드라이브를 쓰고 있나" (My PC)

`umount`가 `target is busy`로 실패하면 `/proc/<pid>/cwd`와 `/proc/<pid>/fd/*` 링크가 그 마운트 폴더 아래를 가리키는 프로세스를 찾아 보여 줍니다.

- `lsof`, `fuser`는 쓰지 않습니다. 최소 설치에 없는 경우가 있습니다.
- 다른 사용자의 프로세스는 root가 아니면 링크를 읽을 수 없어 목록에서 빠집니다. 이때는 기존의 일반 안내문만 나옵니다. sudo로 다시 읽는 것은 하지 않았습니다(안내 한 줄을 위해 비밀번호를 다시 묻지 않기 위해).
- 프로세스 하나당 살펴보는 열린 파일은 4096개까지입니다.
