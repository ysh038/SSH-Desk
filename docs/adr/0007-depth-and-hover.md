# ADR 0007 — 입체감과 hover

- 상태: 채택 (2026-11-19)
- 관련: SPEC 7.1, 7.7, compat-matrix M7

## 배경

화면이 선으로만 그려져 "창이 떠 있다"는 느낌이 약했다. 터미널은 글자 칸 단위라는 한계가 있지만 색 면, 그림자, 포인터 반응은 낼 수 있다.

## 결정

1. **제목줄은 색 띠로 그린다.** 활성 창은 청록, 비활성 창은 회색. 버튼은 3칸씩(` _ `, ` ^ `, ` x `)으로 위치와 크기는 이전의 `[_][^][x]`와 같다. 리눅스 콘솔 글꼴에 없는 글자를 쓰지 않으려고 ASCII만 쓴다.
2. **그림자는 글자를 지우지 않고 색만 어둡게 바꾼다.** 오른쪽 2칸, 아래 1줄. 창은 바탕화면 영역 안에서만, 메뉴와 대화상자도 작업표시줄을 덮지 않는다.
3. **256색 이상에서는 창 바탕을 팔레트 235번(짙은 회색)으로 그린다.** 바탕이 검정이면 검은 그림자와 붙어 보여서다. 16번 이상 팔레트 색은 터미널 테마와 무관하게 같은 색이라 고정값으로 쓴다. 16색 이하에서는 이전처럼 검정 바탕이고 그림자는 검정 면이다.
4. **hover는 그리는 쪽이 판단한다.** 캔버스가 포인터 위치를 들고 있고, 위젯은 그린 뒤 "이 영역은 누를 수 있다"(`Surface.Hot`)고 알리거나 그리기 전에 묻는다(`Surface.Hovered`). 창 관리자는 포인터 바로 아래의 창을 그릴 때만 위치를 알려 주므로 가려진 창은 반응하지 않는다. 앱에 마우스 이동 이벤트를 전달하지 않는다(터미널 창 안 프로그램에 원치 않는 입력이 들어가는 것을 막는다).
5. **포인터 이동 보고(1003)는 설정을 따른다.** 기본은 끔(사용자 결정, 2026-11-19): 폐쇄망 서버에 ssh로 붙는 환경이라 통신량이 늘어나는 기능은 원하는 사람만 켠다. 꺼져 있으면 터미널에 이동 보고 자체를 요청하지 않는다.
6. **키를 누르면 강조를 숨긴다.** 키보드로 목록을 움직일 때 선택 줄과 hover 줄이 둘 다 보이는 혼란을 피한다.

## 버린 대안

- 유니코드 버튼(`─ □ ✕`), 둥근 모서리, 1/8 블록 그림자: 콘솔 글꼴에 없거나 폭이 터미널마다 다르다.
- 밝은 바탕 테마: 문법 색과 터미널 창 색을 전부 다시 맞춰야 해서 이번 범위에서 제외.

## 확인하지 못한 것

- iTerm2, Terminal.app, Windows Terminal, 리눅스 콘솔에서의 실제 색과 이동 보고 동작(compat-matrix M7).
- 지연이 큰 ssh 연결에서 이동 보고가 주는 부담.
