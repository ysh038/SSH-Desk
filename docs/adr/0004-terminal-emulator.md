# ADR 0004: 터미널 창: VT 에뮬레이터 선택과 키 라우팅

- 상태: **채택** (2026-11-05)
- 관련: SPEC 7.5, 8.3, [ADR 0002](0002-keymap.md), [keyboard.md](../keyboard.md)

## 1. VT 에뮬레이터 선택

후보 두 개를 같은 시퀀스 묶음으로 비교했습니다(스파이크 코드는 버림, 결과만 기록).

| 항목 | charmbracelet/x/vt | hinshun/vt10x |
|---|---|---|
| 줄바꿈, CR/LF | ✅ | ✅ |
| **한글(와이드 문자) 폭** | ✅ `한글ab` → 커서 6 | ❌ 커서 4 (폭 처리 없음) |
| 오른쪽 끝 칸의 와이드 문자 | ❌ 글자가 사라짐 → **패치로 해결** | ❌ |
| 대체 화면(?1049) | ✅ | ✅ |
| 스크롤 영역(DECSTBM) | ✅ | ✅ |
| 문자/줄 삽입·삭제, 지우기 | ✅ | ✅ |
| 커서 위치 응답(DSR 6n) | ✅ | ✅ |
| 단말 속성 응답(DA1) | ✅ | ❌ 응답 없음 |
| 탭, DEC 선 그리기 문자 | ✅ | ✅ |
| 스크롤백 | ✅ (내장) | ❌ |
| 모드 변경 콜백(마우스, 붙여넣기 등) | ✅ | 플래그 조회만 |
| 처리 속도 (120×40, 9MB 로그) | 약 4 MB/s | 약 41 MB/s |
| 유지보수 | 활발 (2026-11 커밋) | 2022년 이후 정체 |
| 라이선스 / CGO | MIT / 없음 | MIT / 없음 |

**결정: charmbracelet/x/vt** (`third_party/vt`에 패치한 사본, go.mod `replace`).
- 한글 폭 처리는 필수 요구사항(CLAUDE.md 규칙 5)인데, vt10x는 폭 처리 자체가 없어서 고치는 범위가 큽니다.
- x/vt의 결함은 두 가지였고, 둘 다 몇 줄로 고쳤습니다(`third_party/vt/TUIDESK_PATCH.md`).
  1. 줄 오른쪽 끝에 남은 칸보다 넓은 글자가 오면 버려지던 문제 → xterm처럼 다음 줄로 넘깁니다.
  2. `closed` 플래그 경쟁 상태(`go test -race`로 발견) → `atomic.Bool`로 바꿨습니다.
  - 업스트림에 반영되면 사본을 지웁니다.
- 속도: 4 MB/s는 초당 약 5만 줄입니다. 사람이 보는 출력으로는 충분합니다.
  - 프로파일 결과 대부분이 화면 스크롤 시 줄 메모리 재할당이었습니다.
  - `cat` 거대 파일 같은 경우를 대비해 출력은 UI 한 차례에 256KB씩만 처리하고, 쌓인 출력이 1MB를 넘으면 pty 읽기를 멈춥니다(백프레셔). 그래서 그동안에도 키 입력(Ctrl+C)은 바로 반응합니다.
- 의존성: ultraviolet, x/ansi 등 MIT 모듈이 늘었습니다(THIRD_PARTY_NOTICES.md).
  - x/ansi가 OSC 8 링크 처리에 `net/url`을 씁니다. 순수 문자열 파싱이고 네트워크 입출력이 없어서 lite 빌드 규칙(규칙 3) 위반이 아닙니다.
  - `make check-lite`는 `net`, `net/http`, `crypto/tls` 등은 막고 `net/url`, `net/netip`만 허용합니다.

PTY는 **creack/pty**(MIT, 순수 Go)를 씁니다. `CGO_ENABLED=0` 리눅스 정적 빌드가 됩니다.

## 2. 구조

- `internal/apps/terminal`
  - `encode.go`: 키·마우스·붙여넣기를 바이트로 바꾸는 순수 함수(xterm 규칙, 단위 테스트)
  - `session.go`: pty와 프로세스, 입출력 고루틴
  - `app.go`: 창
- 에뮬레이터는 UI 고루틴에서만 만집니다. pty 출력은 읽기 고루틴이 모아서 `Post`로 넘깁니다. 에뮬레이터 응답(DSR, DA)과 키 입력은 쓰기 고루틴 하나가 pty에 씁니다.
- 화면 셀: `wm.Cell`에 임의 색(팔레트 256색, 트루컬러)과 속성을 담는 `StyleTerm`을 추가했습니다. 리눅스 콘솔에서는 tcell이 8/16색으로 맞춰 줍니다.
- 콘솔 글꼴에 없는 와이드 문자는 `?`로 보여 줍니다(폭은 유지).
- 환경변수: `TERM=xterm-256color`, `COLORTERM=truecolor`, `TUIDESK=1`. `TUIDESK_SOCKET`은 full 빌드(Phase 5)에서 추가합니다.

## 3. 키 라우팅 (결정)

터미널 안 프로그램은 F1~F10, Ctrl+W, Ctrl+Q, Tab 같은 키를 직접 씁니다(htop F6/F9/F10, mc F1~F10, 셸 Ctrl+W). 그래서:

- **터미널 창이 포커스이면 모든 키를 프로그램에 보냅니다.** 데스크톱 단축키(F9, F6, Ctrl+W 등)도 프로그램이 받습니다.
- **예외는 Ctrl+] 하나**입니다. 누르면 터미널 메뉴가 열립니다.
  - 메뉴 항목: 붙여넣기, 선택 복사, 화면 텍스트 복사, 스크롤백, 다음/이전 창, 데스크톱 메뉴, 창 메뉴, Ctrl+] 보내기, 다시 시작, 닫기
  - 메뉴 항목마다 한 글자 단축키가 있어서 `Ctrl+]` `n`처럼 두 번 눌러 쓸 수 있습니다.
  - Ctrl+]는 telnet의 탈출 키와 같고, 프로그램이 거의 쓰지 않습니다. Terminal.app, 리눅스 콘솔, PC 키보드 모두에서 0x1D로 전달됩니다(콘솔 VM 확인).
- 마우스는 항상 데스크톱이 먼저 처리합니다. 제목 줄, 테두리, 버튼은 그대로 동작합니다.
- 터미널 창을 열 때 "Keys go to the program · Ctrl+] opens the terminal menu" 알림을 띄웁니다.

## 4. 마우스, 복사, 스크롤백

- 프로그램이 마우스 모드(?1000/1002/1006, ?9)를 켜면 마우스를 그대로 전달합니다(SGR 또는 기존 인코딩).
  - 우클릭과 가운데 클릭은 데스크톱이 클릭 단위로만 넘기므로 press와 release를 함께 보냅니다.
  - 버튼을 누르지 않은 이동(?1003)은 tuidesk가 받지 않으므로 보낼 수 없습니다.
- 마우스 모드가 꺼져 있으면:
  - 드래그로 선택하면 손을 뗄 때 복사합니다(내부 클립보드와 OSC 52).
  - 휠은 스크롤백을 움직입니다. 대체 화면(less, man)에서는 ↑/↓ 키 세 번으로 보냅니다.
  - 우클릭은 터미널 메뉴입니다.
- 키보드 대체: 메뉴 › Copy screen text, Scroll back…(방향키, PgUp/PgDn, Esc). 콘솔에는 Shift+PgUp이 없어서 메뉴로 엽니다.
- 스크롤백은 5000줄입니다.

## 5. 종료와 닫기

- 셸이나 앱이 코드 0으로 끝나면 창을 닫습니다.
- 0이 아니면 "Process exited (code N)" 띠를 보여 주고, Enter로 닫습니다.
- 파일 관리자에서 실행한 파일(Hold)은 결과를 읽을 수 있게 코드와 상관없이 창을 남깁니다.
- 셸 프롬프트가 아닌 프로그램이 포그라운드에 있으면 창을 닫거나 tuidesk를 끝낼 때 확인합니다.
  - 포그라운드 프로세스는 TIOCGPGRP로 확인하고, 이름은 리눅스 `/proc/<pid>/comm`에서 읽습니다.

## 6. 외부 앱 매니페스트 (SPEC 8.3 1단계)

- `~/.config/tuidesk/apps/*.toml`에 `name`, `icon`, `command`, `cwd`, `hold`를 씁니다.
  - `command`는 `/bin/sh -c`로 실행합니다.
  - `cwd`는 경로, `~`, `{selected_dir}`(포커스된 파일 관리자에서 고른 폴더) 중 하나입니다.
  - 예시는 `docs/examples/apps/`에 있습니다.
- 런처(F9) 아래쪽에 앱 목록이 나옵니다. 바탕화면에는 `[[desktop_icon]] app = "<name>"`으로 올립니다.
- 잘못된 파일은 건너뛰고 알림으로 알려 줍니다.
